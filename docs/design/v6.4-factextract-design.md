# Mnemosyne OS v6.4 Design: Fact Extraction Pipeline

> Historical design doc — written as "Mnemosyne OS" (since renamed to Minnas). Content preserved as-is.

> 2026-08-05 | Basis: LongMemEval attribution finding (#6293) — the real gap is a missing "fact extraction" layer

## Background

LongMemEval evaluation shows: Mnemosyne's retrieval core is healthy, but "fact-level memory" is missing —
external products (Mem0) flatten conversations into facts via extract-and-retrieve before searching;
our distill step only extracts "knowledge/pitfalls", not "personal-info facts" (graduation/commute/shift/preferences).
Evaluating by retrieving raw conversation directly = finding a needle in a haystack (sim 0.2), 16.7%.

## Goal

Conversational memory (session/worklog) → fact extraction → user-profile facts (preference/knowledge) → retrievable.

## Design points (all lessons learned from evaluation)

1. **Short-text, per-item extraction**: call the LLM independently for each memory, don't concatenate long context
   (Doubao lite misses deep answers on 13k-character long sessions, but short-text extraction is reliable)
2. **Non-JSON mode**: call_llm outputs "- fact" line format, parsed via regex
   (Doubao json_mode returns empty for prompts >2500 characters — verified in practice)
3. **tier3 lite**: cheap and sufficient (extraction is a simple task)
4. **Extract only, never fabricate**: hard prompt constraints + explicit rules
5. **ANN dedup gate**: reuse distill's dedup_check (>0.92)
6. **Heat 0.65**: extracted facts are functional memory, inherently important
7. **Provenance**: metadata fact_extracted_from / fact_extracted_at / source_category
8. **Retry on failure**: empty LLM returns are not marked done, retried on the next cron pass

## Implementation: tmt/factextract.py

```
Candidate filter: category IN (session,worklog) AND metadata->>'fact_extracted' IS NULL
  → per item: signal filter (skip small talk) → extract_facts(content) → per-fact dedup + insert
  → mark source fact_extracted=true
Classification: preference/personal-info keywords → preference; otherwise → knowledge
Usage: python tmt/factextract.py [--batch N] [--dry-run]
```

## Validation

1. Local mock: extraction parsing / classification / dedup logic
2. GZ dry-run: 20 real records
3. LongMemEval group B retest: once the extraction layer is correctly implemented, the score should improve significantly (target ≥40%)

## Not doing (pragmatism principle)

- No graph modeling (AGE already exists; the fact layer starts with flat rows)
- No full recompute (start from new data only)
- No dependency on json_mode / tier4 code
